# JagatData API Documentation

Base URL (local): `http://127.0.0.1:8000`
Interactive Swagger docs auto-generated by FastAPI: `http://127.0.0.1:8000/docs`

All endpoints (except `/api/auth/login`, `/api/auth/roles`, `/api/health`) require:
```
Authorization: Bearer <token>
```
obtained from `/api/auth/login`.

## Auth
| Method | Path | Description |
|---|---|---|
| POST | `/api/auth/login` | `{username, password}` → `{token, session}` |
| GET | `/api/auth/roles` | List demo accounts (Admin/Officer/Reviewer) |

## Connectors / Ingestion
| Method | Path | Description |
|---|---|---|
| GET | `/api/connectors` | List registered connectors + recent sync logs |
| POST | `/api/connectors/{department}/upload` | Multipart CSV upload → maps to common schema, validates, ingests |
| POST | `/api/connectors/{department}/load-sample` | Loads bundled sample CSV for quick demo |

`department` ∈ `Health`, `Education`, `Welfare`

## Duplicate Detection
| Method | Path | Description |
|---|---|---|
| POST | `/api/matching/run` | Runs blocked pairwise comparison across all ingested source records |
| GET | `/api/matching/candidates?status=pending` | List candidate pairs with score + explainable reason |
| POST | `/api/matching/candidates/{match_id}/resolve` | `{action: "confirm"\|"reject", comment}` — officer/reviewer decision |

## Unified Citizen Profile
| Method | Path | Description |
|---|---|---|
| GET | `/api/citizens?q=` | List/search unified (golden) citizen records |
| GET | `/api/citizens/{citizen_id}/profile` | Full 360° profile: linked records, applications, grievances, beneficiary records, consents |
| GET | `/api/dashboard/summary` | Aggregate KPIs for the dashboard |

## Consent
| Method | Path | Description |
|---|---|---|
| POST | `/api/consents/request` | `{citizen_id, requesting_department, data_scope, purpose, validity_days}` |
| POST | `/api/consents/{consent_id}/decide` | `{decision: "granted"\|"denied"\|"revoked"}` |
| GET | `/api/consents?citizen_id=` | List consent records |

## Applications (unified tracking + configurable workflow)
| Method | Path | Description |
|---|---|---|
| POST | `/api/applications` | `{citizen_id, department, service_name, priority, notes}` |
| GET | `/api/applications?citizen_id=&department=&status=` | Filterable list |
| PATCH | `/api/applications/{application_id}/status` | `{new_status, comment, assigned_officer}` |
| GET | `/api/applications/{application_id}/history` | Full workflow status history |

Valid statuses: `submitted`, `under_review`, `additional_info_requested`, `approved`, `rejected`, `completed`

## Grievances
| Method | Path | Description |
|---|---|---|
| POST | `/api/grievances` | `{citizen_id, department, subject, description, priority}` |
| GET | `/api/grievances?citizen_id=&status=` | Filterable list |
| PATCH | `/api/grievances/{grievance_id}` | `{status, assigned_officer}` |

## Beneficiaries
| Method | Path | Description |
|---|---|---|
| GET | `/api/beneficiaries?citizen_id=&department=` | Scheme/beneficiary outcome records |

## Monitoring / Data Quality / Audit
| Method | Path | Description |
|---|---|---|
| GET | `/api/monitoring/sync-logs` | Connector sync history incl. failed syncs |
| GET | `/api/monitoring/data-quality` | Per-department clean vs flagged record counts |
| GET | `/api/audit-logs?entity_type=&limit=` | Full audit trail |

## Reports
| Method | Path | Description |
|---|---|---|
| GET | `/api/reports/export/{report_type}` | `report_type` ∈ `applications, grievances, citizens, matches, audit` → returns CSV string |

## Event Notifications (outbound to n8n)
JagatData POSTs a JSON body `{event, payload, timestamp}` to `N8N_WEBHOOK_URL` for these events:
`data_ingested`, `duplicate_candidates_found`, `match_resolved`, `consent_requested`,
`consent_decision`, `application_submitted`, `application_status_changed`,
`grievance_filed`, `grievance_status_changed`.
